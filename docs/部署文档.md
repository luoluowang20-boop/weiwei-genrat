# 从本地网站到正式域名

你已经有 GitHub、Vercel、Google 账号。按顺序完成下面操作，每步都附有成功标志。平台菜单可能调整，相关官方说明已于 2026-10-10 核对。本文中的 `你的域名` 是提示文字，必须换成实际购买的域名。

## 1. 先在电脑上运行

按项目 README 启动，打开 http://localhost:3000。复制一个编号到记事本，确认与页面一致；点击 Generate new，确认编号变化；刷新后确认重新生成。

成功标志：三个操作都正常。用完按 Ctrl+C 可以关闭本地服务。

## 2. 把代码放到 GitHub

打开 [GitHub](https://github.com/)，新建仓库，名字填 `uuid-generator`，可选择 Private。不需要勾选自动添加 README。

在空仓库页面点击 uploading an existing file，或 Add file → Upload files。把本项目中的 `src`、`scripts`、`tests`、`docs` 文件夹，以及 `package.json`、`vercel.json`、`README.md`、`.gitignore` 上传，点击 Commit changes 保存。Windows 看不到 `.gitignore` 时，可在资源管理器打开“隐藏的项目”，或在 GitHub 用 Add file → Create new file 添加同名文件并复制内容。

不要上传 `dist`、`node_modules`、`.env`、`.vercel`。上传的是 uuid-generator 文件夹里面的内容，不是额外再套一层文件夹。

成功标志：仓库首页能直接看到 package.json、vercel.json 和 src 文件夹。

## 3. 部署到 Vercel

打开 [Vercel](https://vercel.com/)，进入 Add New → Project，连接 GitHub 后找到刚创建的仓库并 Import。只授权需要使用的仓库即可。

核对以下设置：

| 设置项 | 填写内容 |
| --- | --- |
| Framework Preset | Other |
| Root Directory | 仓库根目录，通常保持默认 |
| Build Command | `node scripts/build.mjs` |
| Output Directory | `dist` |
| Install Command | 保持默认，本项目无第三方依赖 |

代码中的 vercel.json 已包含构建及输出设置。点击 Deploy，等待 Ready。以上设置作用见 [Vercel 构建说明](https://vercel.com/docs/builds/configure-a-build)。

打开平台分配的 `https://项目名.vercel.app` 地址，检查生成和复制功能。用未登录 Vercel 的浏览器再访问一次，确认正式站点公开可用。只需要调整正式站点的访问设置，不必取消预览部署保护。

成功标志：部署状态 Ready，公开网址可访问，工具可用。此时先测试功能，购买域名后再完成搜索准备。

## 4. 买一个预算内的域名

域名就是你的网站地址，不包含 https://。在域名注册商的网站搜索喜欢的名称并检查是否可购买。选普通域名，避免“精品域名”或高价转售。无须购买建站套餐、邮箱、独立服务器或额外证书。

付款前分别查看第一年注册价、第二年起续费价、税费与换汇费用。只有注册总价和当前续费总价都在每年 100 元人民币以内，才符合你的预算。不要仅根据首年优惠决定；未来价格仍可能调整。本文不承诺某个后缀或域名一定低于预算。

购买完成后按注册商要求验证邮箱，记录到期日。选择自动续费前先确认价格和扣费方式。

成功标志：账户域名列表里出现你的域名，并能找到 DNS 或“域名解析”管理页面。

## 5. 把域名连接到 Vercel

在 Vercel 项目进入 Settings → Domains → Add Domain，输入实际域名，例如你购买的是 my-example.com，就填 my-example.com。本文推荐将不带 www 的域名作为主地址；如果平台建议添加 www，也添加，并设置 www 跳转到不带 www 的地址。

Vercel 会显示需要添加的 DNS 记录。DNS 可以理解为“告诉浏览器这个域名对应哪个网站”的地址记录。到购买域名的平台打开解析管理，逐条复制 Vercel 显示的记录：类型、名称和记录值。根域名的名称常写 `@`，www 的名称写 `www`；具体按两边控制台提示填写。记录值用你项目当时显示的内容，不照抄网上的旧 IP。保留已有邮箱和其他用途的记录；如果同一名称存在冲突，只处理那个冲突项。

本流程保持注册商管理 DNS，不需要更换域名服务器。相关设置见 [Vercel 绑定域名说明](https://vercel.com/docs/domains/working-with-domains/add-a-domain)。

回到 Vercel 等待配置有效和 HTTPS 证书就绪。若尚未生效，检查记录内容，留时间等待解析更新；不要不断修改记录。

成功标志：用 `https://实际域名` 打开工具，浏览器没有证书警告；www 地址按你的设置跳转到主地址。

## 6. 让站点地图使用真实域名

进入 Vercel 项目 Settings → Environment Variables，新增：

- 名称：`SITE_URL`
- 值：`https://实际域名`（如主地址带 www，这里也必须带；不要写页面路径或空格）
- 环境：Production

保存后进入 Deployments，找到正式部署并点击 Redeploy。只修改环境变量而不重新部署，不会更新文件。

成功后依次打开：

```text
https://实际域名/robots.txt
https://实际域名/sitemap.xml
```

robots.txt 应包含 `Allow: /` 和实际域名的 sitemap 地址；不应该有 `Disallow: /`。sitemap.xml 应只列出实际首页地址。查看首页源代码，搜索 canonical，确认 href 是主域名；搜索 robots，确认是 `index,follow`。

预览部署会保持禁止索引。没填写 SITE_URL 时，程序可能使用 Vercel 提供的正式部署网址；绑定自有域名后仍应明确设置 SITE_URL。若没有任何正式网址，构建会禁止索引且地图为空，避免发布虚假网址。

## 7. 验证 Google Search Console

打开 [Google Search Console](https://search.google.com/search-console)，登录 Google 账号，添加资源，选择“网域 / Domain”，填不带 https:// 的根域名，不带路径。

Google 会给出一条 TXT 记录，内容通常以 `google-site-verification=` 开头。复制完整内容，回到域名注册商的解析管理，新增 TXT 记录，根域名名称按平台规则填 `@` 或留空，值粘贴 Google 给出的完整文本，保存。

回到 Google 点击验证。如果暂时失败，核对名称、记录值和 DNS 管理位置，并等待解析更新后重试。验证成功后保留这条 TXT 记录。Google 的具体验证方法见 [所有权验证说明](https://support.google.com/webmasters/answer/9008080?hl=zh-Hans)。

成功标志：Google 显示所有权已验证，可以打开该网站的管理页面。

## 8. 提交站点地图

在 Search Console 选择刚验证的资源，打开“站点地图 / Sitemaps”。提交完整地址 `https://实际域名/sitemap.xml`。如果输入框已经固定显示主域名，则只填后面的 `sitemap.xml`，不要重复填写域名。

提交后查看记录和处理结果。如果暂时提示无法获取，先用未登录的浏览器直接打开地图；检查是否用了正确主域名、是否返回 XML、是否被登录保护挡住，再回到 Google 重试。若可以正常访问但 Google 尚未处理，稍后复查，不必反复删除提交。Google 的处理结果说明见 [站点地图报告](https://support.google.com/webmasters/answer/7451001?hl=zh-Hans)。

成功标志：提交记录存在，后续处理状态为成功。没有立即显示收录不等于部署失败，不需要等到有排名才算练习完成。

## 9. 最后检查与以后修改

- [ ] 域名打开后自动显示 UUID，复制和重新生成正常。
- [ ] 手机和电脑都能使用。
- [ ] 正式域名使用 HTTPS，访客无须登录。
- [ ] robots.txt 开放抓取，sitemap.xml 只有正确主域名。
- [ ] Search Console 验证成功，站点地图已提交并检查结果。

以后改页面，编辑 src 下文件并提交到 GitHub 的正式分支，Vercel 会根据仓库连接设置重新部署。不要只编辑 dist，因为下次构建会覆盖它。正式分支部署失败时，先看 Vercel 的构建日志；404 通常先检查仓库根目录和输出目录是否与第 3 步一致。

练习交付到此为止。收录、点击和排名留作后续观察。
